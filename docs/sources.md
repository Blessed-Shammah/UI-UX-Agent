# Sources and research boundaries

Reviewed on **2026-10-15**. These links inform the toolkit; source authors do not endorse it. The instructions are original synthesis, not copies of paid templates or external skill libraries.

## Accessibility and platform behavior

- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/): authoritative web accessibility criteria. The web reference distinguishes AA minimum targets from larger touch recommendations.
- [Radix accessibility documentation](https://www.radix-ui.com/primitives/docs/overview/accessibility): responsibilities when composing interface primitives.
- [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines): platform-specific guidance for Apple products.
- [Microsoft Fluent 2](https://fluent2.microsoft.design/): design-system and Microsoft platform reference.
- [Web Vitals](https://web.dev/articles/vitals): performance measures and field assessment. Local checks do not establish real-user percentiles.

## Foundations and assets

The [resource catalog](../resources/catalog.json) links official repositories and author documentation. Its template entries are starting points for investigation, not claims of superior design or verified runtime quality. Repository licenses do not automatically cover every image, font, plugin, or paid edition. Inspect exact revisions before adoption.

The shortlist intentionally stays small. Add resources based on an actual task and maintained evidence, rather than collecting hundreds of overlapping links.

The npm planner's [routing registry](../resources/routing.json) adds decision metadata for blocks, component systems, expressive enhancements, and native alternatives. See [resource decisions](resource-decisions.md) for Tailark, shadcn, and PrebuiltUI source distinctions and [integration references](npm-and-integrations.md) for supported project-local skill locations.

## Agent workflow

- [Building effective agents](https://www.anthropic.com/engineering/building-effective-agents): workflow/agent distinctions and implementation tradeoffs.
- [Lost in the Middle](https://arxiv.org/abs/2307.03172): research on context use under the paper's evaluated conditions.

These sources motivate scoped context and explicit validation. They do not prove this toolkit improves visual quality, conversion, accessibility conformance, or delivery speed. Numeric spacing/type/motion suggestions elsewhere are design heuristics unless explicitly attributed to a standard. Validate them against the actual product.
